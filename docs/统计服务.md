# Zashboard 流量统计首版

本 Fork 在上游 Zashboard 的原有代理卡片、连接表格及设置中集成累计统计与设备绑定；“流量统计”页面保留为汇总与历史查询入口。Python 常驻服务采集 Mihomo，SQLite 保存统计及设备绑定；关闭浏览器不影响采集。服务只读访问 Mihomo 的 `/connections`、`/rules`，不修改 Nikki 配置，不重启内核。

## 原界面集成

- **代理组卡片**：保留组名、当前选择、实时速度和预览，将流量值紧接类型和数量，组内固定 6px 间距并用中点分隔，不加“累计”标签，保持原卡片高度；上传、下载放在悬停提示与点击详情中。点击累计值打开组用量弹层，不触发节点选择或卡片展开；桌面与手机双列均支持。
- **月度口径**：按连接实际 `chains` 中的每个名称记账，同一连接中的重复名称只计一次。中间组、外层策略组及最终节点分别累计，切换当前节点不会清零；卡片显示北京时间本月用量，每月 1 日自动从零开始，历史按月保存。嵌套组有包含关系，不能把各卡片相加当作全局总量。
- **主机名列**：连接表格在来源 IP 旁独立增加“主机名”，来源 IP 保留内核原值；支持原有列显隐、排序、搜索、高亮和分组。首次升级只补充一次列，后续不覆盖用户列设置。
- **就地绑定**：点击主机名单元格或原连接详情中的设备入口，使用同风格弹层编辑名称与多个 IP；保存后原表格和手机连接卡片同步更新。空来源 IP 不提供绑定操作。
- **内网自动开通**：默认 `require_auth: false`。同源页面自动发现统计服务与采集源，不需要令牌、启用按钮、服务地址或采集源 ID。卡片累计、设备绑定和历史统计共用自动加载逻辑，新浏览器也直接可用。
- **可选认证模式**：仅显式设置 `require_auth: true` 时才使用令牌与高级连接设置。默认内网部署不经过这些步骤，设备名称和统计始终由 SQLite 共享。
- **异常显示**：服务暂不可用时保留上次成功取得的卡片数值并标记“未更新”，首次加载时显示简短加载状态，失败时显示暂不可用，不显示启用入口，也不把失败当作 `0 B`。

## 功能与统计口径

- 按设备、来源 IP、分流策略、代理节点、入口 VPS、落地 VPS、目标域名、目标 IP 汇总上传与下载。
- 今日、昨日、最近七天、本月查询；时间范围按 Asia/Shanghai 计算。支持设备、策略、来源 IP、入口及落地 VPS 的交叉筛选。
- 分钟粒度保存，每小时绘制趋势，排行最多返回 500 项，总计仍包含全部匹配数据。
- 一台设备绑定多个 IPv4 / IPv6 地址，独立主机名列与统计共享服务端名称。服务端绑定名称优先于浏览器原有 IP 标签，未绑定地址继续使用上游标签与反向 DNS，未获得名称时显示“—”；来源 IP 始终保留原值。
- 每个节点可指定入口与落地 VPS，同一 VPS 的多个节点自动聚合；入口与落地是两个独立维度，不相加。
- 映射按连接 `chains[0]` 的完整节点名称精确匹配。策略优先使用 `/rules` 中命中规则的目标，匹配不到时使用代理链最外层。规则相同但目标不同的子规则等复杂情况可能有歧义，应核对真实样本。
- DIRECT 等内置出口标为“不适用”，其他没有 VPS 映射的节点标为“未映射”。源地址缺失显示“本机/未知”，目标 IP 是内核报告值，可能为 fake-ip。

### 精度边界

这是连接采样统计，不是网卡计量或 VPS 供应商账单。只覆盖经过该 Mihomo 的连接，不包含绕过 Nikki 的设备通信、VPS 的其他业务或隧道协议开销。

首次采样只建立基线，不把启动前累计流量导入历史。后续对连接累计计数取增量；新观察到的连接累计量记在观察到的分钟。内核总计数回退、采集请求失败后的恢复、采样间隔异常时重新建立基线，不把跨断线期间的累计量错误分摊到恢复时刻。计数器回退可检测常见内核重启，无法保证识别每一种重启情况。

短连接可能在两个快照之间结束，连接消失前最后一段流量也可能丢失。页面同时显示内核总增量、全部连接归属量和事件计数。二者统计时点不同，归属量也可能暂时超过总增量；它们不是可以强制配平的账目。首次基线及断线期间不在总增量中，因此差额不代表全部漏失流量。界面显示的差额为非负值，不是精确误差率。

### 设备与节点映射

绑定/解绑从保存后生效，历史流量中的设备 ID 不改写，避免 DHCP 地址复用导致历史串设备。一个 IP 同时只能绑定一台设备，重新分配时先在旧设备清空或删除该地址，再绑定新设备。设备改名更新历史显示名称。解绑后设备条目保留，以维持历史关联。

VPS 映射调整也只影响后续样本，历史继续显示当时的入口/落地。节点改名后需要添加新名称映射。第一版手工维护设备和节点，不自动猜测 DHCP、MAC 或中转拓扑，也不向历史数据回填新映射。

## 本地启动

依赖 Python 3.10+（含 `sqlite3`）以及构建前端所需的 Node.js 22.12+ / pnpm。构建时请遵循上游当前 Vite / pnpm 的运行时要求，建议 Node.js 24。

在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm type-check
pnpm build:no-fonts
cp stats-service/config.example.json stats-service/config.json
chmod 600 stats-service/config.json
```

默认内网模式无需统计令牌，`api_token` 可以留空。`controller` 填实际 Mihomo API 地址，`controller_secret` 填已有内核密钥，也可通过 `MIHOMO_SECRET` 设置。只有显式启用 `require_auth: true` 才要求至少 24 字符的统计令牌，可用 `STATS_API_TOKEN` 设置。

```bash
python3 stats-service/service.py --config stats-service/config.json
```

默认监听 `127.0.0.1:9099`，同时提供 `dist/` 页面和 `/api/stats/` 接口。打开 `http://127.0.0.1:9099`，先在 Zashboard 中配置实际的 Mihomo 后端，再进入“流量统计”：

1. 代理卡片标题自动显示累计合计，无需手工启用或输入令牌。
2. 悬停累计查看上传/下载，点击查看详情。
3. 在连接表格“主机名”列点击“—”或已有名称，就地维护机器名与多个 IP。
4. VPS 对应关系及历史汇总仍可进入“流量统计”，该页面也自动加载，不显示内网连接表单。

内网同源部署自动关联当前后端，不依赖此前浏览器是否保存过令牌。可选认证或异源部署仍可使用高级连接配置。不能把同一数据库改接其他采集源或 `controller`；服务会拒绝启动，切换来源时使用新数据库。数据库路径及 `static_dir` 相对进程工作目录解析。

### 开发模式

前后端分别运行：

```bash
pnpm dev --host 127.0.0.1
python3 stats-service/service.py --config stats-service/config.json
```

开发页面填写统计服务地址 `http://127.0.0.1:9099`；配置里的 `allowed_origins` 加入页面的完整来源（协议、主机、端口），例如 `http://localhost:5173` 或 `http://127.0.0.1:5173`，不支持通配符。HTTPS 页面应连接 HTTPS 统计 API，避免浏览器混合内容限制。

## 部署

优先在能持续访问 Mihomo API 的常驻设备运行。50.2 上部署前，先检查 Python/SQLite、可用内存、持久存储与写盘条件；本首版不自动安装路由器软件或替换现有面板。数据量取决于设备数、连接目标数和维度组合，分钟明细默认保留 90 天，每小时清理过期行；每月的代理链与来源 IP 汇总长期保留。SQLite 使用 WAL，按采样批次提交；不建议直接放在路由器容量小的内部闪存中。删除过期行会复用空页，不会立即缩小数据库文件。

### Linux 常驻服务

仓库提供 `stats-service/zashboard-stats.service`。安装到 `/opt/zashboard`、创建专用用户、准备私有配置及持久目录并授予该用户读写权限后，再按实际路径调整模板。进程必须能写数据库所在目录（包括 `-wal`、`-shm` 文件）。模板不包含生产凭据。

也可以使用 `Dockerfile.stats` 构建包含前端的镜像：

```bash
docker build -f Dockerfile.stats -t zashboard-stats:local .
```

容器内设置配置 `listen` 为 `0.0.0.0`、`database` 为 `/data/stats.sqlite3`、`static_dir` 为 `/app/dist`，挂载私有配置和持久数据卷：

```bash
docker run -d --name zashboard-stats --restart unless-stopped \
  -p 127.0.0.1:9099:9099 \
  -v "$PWD/stats-service/config.json:/config/config.json:ro" \
  -v zashboard-stats-data:/data \
  zashboard-stats:local
```

容器里的 `127.0.0.1` 指容器自身，`controller` 必须填写容器可达的 Nikki 地址。服务默认不使用环境 HTTP 代理请求内核。

对外提供页面时，在可信局域网或 Tailnet 内通过反向代理提供 HTTPS；可仅转发 `/api/stats/`，也可转发完整站点。内网默认不要求统计令牌，同源页面直接使用；跨域来源由 `allowed_origins` 配置。Python 自带 HTTP 服务用于可信网络的首版部署，生产入口建议由成熟反向代理提供连接限制及 TLS。

### OpenWrt / ImmortalWrt 旁路部署

仓库提供 `stats-service/openwrt.init` 与 `stats-service/rollback-openwrt.sh`，用于已有 Python 3.10+ / SQLite 的 OpenWrt 环境。先备份原版 UI，记录当前活动配置、运行配置与 UCI 的哈希、Mihomo PID 和策略组选择；然后准备以下独立位置：

| 内容         | 路径                                       |
| ------------ | ------------------------------------------ |
| 后端         | `/opt/zashboard-stats/service.py`          |
| 前端构建产物 | `/opt/zashboard-stats/dist/`               |
| 私有配置     | `/etc/zashboard-stats/config.json`         |
| 统计数据库   | `/opt/zashboard-stats/data/stats.sqlite3`  |
| procd 服务   | `/etc/init.d/zashboard-stats`              |
| 停用脚本     | `/opt/zashboard-stats/rollback-openwrt.sh` |

复制文件并调整私有配置：`database`、`static_dir` 使用以上绝对路径，`controller` 指向路由器本机 Mihomo API，`listen` 只绑定可信管理地址。配置目录与数据目录设置为 `700`，配置文件设置为 `600`。原版 `external-ui` 不做修改，定制版另开端口。

```bash
chmod 755 /etc/init.d/zashboard-stats /opt/zashboard-stats/rollback-openwrt.sh
/etc/init.d/zashboard-stats enable
/etc/init.d/zashboard-stats start
/etc/init.d/zashboard-stats status
```

启动后核对统计 API 健康、采样数持续增加、原版入口仍正常，以及原版文件哈希、Mihomo PID 和策略选择保持不变。进程异常退出由 procd 拉起；正常退出等待时间设为 20 秒。`procd` 停止命令是异步的，升级时应等待旧监听完全退出，再启动新进程并核对部署文件哈希，避免读到旧进程的健康响应。

回退使用：

```bash
/opt/zashboard-stats/rollback-openwrt.sh
```

脚本只停用并禁止新增服务自启，保留数据库，随后直接访问原版入口。需要再次试用时重新 `enable`、`start` 即可。脚本中的入口提示按本项目的 50.2 目标设置，其他地址部署时请调整提示。

已在真实 OpenWrt 环境验证：新旧页面可同时加载，统计持续增加；执行停用脚本后原版继续可用、数据库保留，重新启动后采集恢复。该验证没有通过重启路由器来测试开机启动；已核对 procd 运行状态和自启链接。具体配置、令牌及部署前快照保留在目标设备与本地私有部署目录，不上传 GitHub。

### 备份与回滚

- 统计数据与前端 `dist/` 分开存放，前端升级不能覆盖数据库及私有配置。
- 在线备份使用 SQLite backup API；不要只复制正在使用的主数据库文件，遗漏 WAL 会丢数据：

```bash
python3 -c 'import sqlite3; s=sqlite3.connect("stats-service/data/stats.sqlite3"); d=sqlite3.connect("/安全位置/stats-backup.sqlite3"); s.backup(d); d.close(); s.close()'
```

- 回滚前停止统计服务，保留当前数据库副本，再切换前端和服务代码；当前 schema 版本为 3，新增 `chain_monthly`、`source_monthly` 与自动名称来源；自动兼容已有 schema 1/2 数据库，不重写原有统计或设备 ID。
- 现有 Nikki/Zashboard 可保留独立入口，首版先旁路验证，不必切换 Nikki 的 `external-ui`。
- 设备绑定、IP、目标域名、数据库、配置及备份都是私有运维数据，不上传 GitHub。仓库 `.gitignore` 与 `.dockerignore` 已排除本地配置和数据；自定义备份路径同样应放在仓库外。

### 卡片累计与历史兼容

卡片的完整代理链累计从首次运行集成版采集器时开始，弹层和悬停提示显示开始时间。旧版只保存了最终节点和单个策略，没有保存完整中间组链路，因此不对旧数据猜测回填。原分钟历史、设备绑定及 VPS 映射全部保留。

卡片读取 `chain_monthly` 的当前自然月（Asia/Shanghai），不会通过清库或删除历史实现“清零”。点击数值可选择历史月份。升级时，仅当旧完整代理链累计的起止时间都在同月内，才精确迁入该月；跨月旧累计不会猜测拆分。来源 IP 月汇总从现存分钟明细回填一次；更早已清理的明细不能重建。`chain_totals` 旧累计表保留以兼容回退。

连接页工具栏的柱状图按钮打开“设备用量”：按 IP 展示本月下载、上传、合计和当前绑定名称，可搜索名称/IP、切换历史月份、点击名称编辑绑定。页面可见时每 10 秒刷新；回到标签页立即更新卡片与主机名，后台默认每 1 秒采样。

OpenWrt 默认启用后台名称识别，依次使用本机 hosts/DHCP、mDNS、网关 PTR 与 NetBIOS；每 5 分钟更新。已得到的 mDNS 名称立即发布，不等全部地址超时。相同 MAC 可关联多个地址，不凭同名合并机器。手动名称优先；自动绑定遇到 IP 的 MAC 变化会终止旧绑定，不改写历史。无法取得可信名称时继续显示“—”，不会凭 IP 编造名称。通用 Python/Docker 部署可显式设置 `discover_hosts: true`（通常仅能看到部署所在局域网），可用 `lan_dns` 指定 PTR 查询服务器。
